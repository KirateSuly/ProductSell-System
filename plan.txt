商品销售管理系统 — 开发计划
Context
基于 prompt.txt 的需求，从零构建一个商品销售管理系统。项目目录当前为空，需要完整搭建前后端工程、数据库、所有业务模块。

技术栈：Vue 3 + Element Plus | Spring Boot 3.2 | MySQL 8.0 | MyBatis-Plus | Spring Security + JWT | Swagger/SpringDoc

功能模块：用户管理、商品管理（含图片上传）、客户管理（自动编号）、订单管理、销售统计图表

3. 后端架构要点
关键依赖
Spring Boot 3.2.x | MyBatis-Plus 3.5.6 | jjwt 0.12.5 | SpringDoc 2.5.0 | Hutool 5.8 | Lombok

统一响应
Result<T> 包装器：{ code, message, data }，配合 GlobalExceptionHandler 统一异常处理。

API 端点（RESTful）
认证: POST /api/auth/login, GET /api/auth/userinfo
用户: GET/POST /api/users, GET/PUT/DELETE /api/users/{id}
商品: 同上 + POST /api/products/upload-image（图片上传）
客户: 同上（创建时自动生成 customer_code）
订单: 同上 + PUT /api/orders/{id}/status（状态变更）
统计: GET /api/statistics/overview|sales-trend|top-products|category-sales|order-status
安全认证（Spring Security + JWT）
SecurityConfig: 禁用 CSRF，无状态 Session，放行 /api/auth/login、Swagger、上传文件路径
JwtAuthenticationFilter: 从 Authorization: Bearer <token> 解析 JWT，设置 SecurityContext
JwtTokenProvider: 生成/验证/解析 Token，24 小时有效期
BCryptPasswordEncoder 加密密码
编号自动生成
CodeGenerator 工具类：格式为 前缀 + yyyyMMdd + 3位序号，查询当天最大编号后递增，synchronized 保证线程安全。客户: KH，商品: CP，订单: DD。

订单创建（核心业务）
@Transactional：插入 order → 生成订单号 → 遍历 order_items 计算 subtotal → 汇总 total_amount → 批量插入 item → 更新 order 总金额。商品名称/价格以快照方式存入 order_item。

统计图表
StatisticsMapper.xml 手写 SQL 聚合查询，支持可选 startDate/endDate 参数。

4. 前端架构要点
关键依赖
Vue 3.4 | Vue Router 4 | Pinia | Element Plus 2.7 | Axios | ECharts 5 + vue-echarts 6

路由设计
/login → LoginView
/ → MainLayout (需认证)
  ├── /dashboard → DashboardView（概览卡片）
  ├── /users → UserManageView（仅 ADMIN）
  ├── /products → ProductManageView
  ├── /customers → CustomerManageView
  ├── /orders → OrderManageView
  └── /statistics → StatisticsView（图表）
路由守卫：未登录跳 /login，已登录访问 /login 跳 /dashboard，角色权限校验。

Axios 封装
请求拦截器：自动附加 Authorization: Bearer <token>
响应拦截器：统一错误提示（ElMessage），401 清 token 跳登录，自动解包 Result 数据
布局
MainLayout = HeaderBar（Logo + 面包屑 + 用户下拉） + SidebarMenu（el-menu 可折叠） + 主内容区（router-view + keep-alive）

页面模式（通用 CRUD 页面）
搜索栏 → 操作按钮 → el-table → el-pagination → el-dialog（表单/详情）

统计页面
4 个概览卡片 + 日期范围筛选 + 折线图（销售趋势）+ 柱状图（热销商品 Top10）+ 饼图（分类销售 + 订单状态分布）

订单管理（最复杂页面）
创建/编辑订单对话框：客户选择 → 动态商品明细表（添加行、选商品、填数量、自动计算小计和总额）→ 提交。状态流转管理。

7. 验证方案
启动验证：后端启动后访问 http://localhost:8080/swagger-ui.html 确认 Swagger 可用；前端 npm run dev 确认页面加载
认证测试：POST /api/auth/login 获取 Token，携带 Token 访问受保护接口
CRUD 测试：通过 Swagger 逐个测试各模块的增删改查、分页、条件查询
图片上传：上传商品图片，确认文件保存到 uploads/ 目录，URL 可访问
订单流程：创建客户 → 创建商品 → 创建订单（含明细）→ 修改状态 → 验证金额计算
统计图表：录入测试订单数据后，访问统计页面，确认图表数据正确渲染
前端交互：测试登录守卫、401 自动跳转、表单验证、删除确认、分页切换、Loading 状态
