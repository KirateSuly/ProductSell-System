# AI 智能问答助手 实现计划

## Context

为进销存管理系统接入一个内嵌侧边 AI 对话窗口。AI 固定扮演"销售进销存顾问"角色，能够用自然语言回答用户关于业务数据（营收、库存、订单等）的查询，并指导系统操作。后端代理调用公有大模型 API，实时注入数据库中的真实业务数据，严格约束 AI 不虚构数据、不回答无关闲聊。

### 当前状态
- 前端：Vue 3 + Element Plus + Pinia + Axios，MainLayout 布局为 el-aside(左) + el-header + el-main
- 后端：Spring Boot + Spring Security JWT + MyBatis Plus
- 已有完整的统计 API（overview, sales-trend, top-products, category-sales, order-status）
- 无任何 AI/聊天相关代码

### 步骤 2：后端 — AI 配置类

**新建**: `backend/src/main/java/com/productsell/config/AIConfig.java`

```java
@Configuration
public class AIConfig {
    @Value("${ai.api.key}")
    private String apiKey;
    @Value("${ai.api.url}")
    private String apiUrl;
    @Value("${ai.api.model}")
    private String model;

    @Bean
    public RestTemplate aiRestTemplate() {
        return new RestTemplateBuilder()
            .defaultHeader("Authorization", "Bearer " + apiKey)
            .defaultHeader("Content-Type", "application/json")
            .build();
    }
    // getters for apiUrl, model...
}
```

**配置文件**: `backend/src/main/resources/application.yml` 新增：
```yaml
ai:
  api:
    key: ${AI_API_KEY:your-api-key}
    url: https://api.deepseek.com/chat/completions
    model: deepseek-chat
```

#### 4.1 固定 System Prompt 设计

```
你是一个专业的进销存管理系统顾问，只能回答与销售、库存、商品、订单、客户管理相关的问题。

## 核心规则（必须严格遵守）
1. 你只服务于"商品进销存管理系统"的业务咨询。
2. 如果用户询问与进销存业务无关的问题（如天气、闲聊、编程、娱乐、政治等），回复："抱歉，我是销售进销存顾问，只能回答商品管理、库存、订单、客户、销售统计等相关问题。请提出业务相关的问题。"
3. 所有数据必须基于下方【当前系统数据】中的真实数字进行分析。
4. 如果用户询问的数据在【当前系统数据】中不存在，回复："暂无该统计数据"。
5. 严格禁止虚构或编造任何金额、数量、日期、人名等数据。
6. 回答中涉及金额时，必须标注货币单位（元/人民币）。

## 你能做的事情
- 查询和分析销售统计（营收、订单量、趋势）
- 分析库存状况（在售/停售、库存不足预警）
- 查询订单状态分布
- 分析客户数据
- 热销商品排行分析
- 指导用户操作系统功能（如何添加商品、如何创建订单等）

## 回答格式要求
- 用清晰的标题分段（如：### 营收概况、### 库存分析）
- 数字用表格或列表形式展示，标注清楚指标名称、数值、单位、对比
- 分析类回答给出简要的趋势解读或建议
```

#### 4.2 实时数据注入

在每个请求到达时，调用 `StatisticsMapper` 查询最新数据，构造如下 JSON 注入到 System Prompt：

```
## 当前系统数据（实时）

### 概览指标
- 在售商品数：{totalProducts}
- 客户总数：{totalCustomers}
- 订单总数：{totalOrders}
- 总销售额：{totalRevenue} 元

### 库存概况
- 在售商品：{activeProducts} 种
- 停售商品：{inactiveProducts} 种
- 低库存预警（库存<10）：{lowStockList} （商品名:库存量）

### 订单概况
- 待处理：{pendingCount} 单
- 已发货：{shippedCount} 单
- 已完成：{completedCount} 单
- 已取消：{cancelledCount} 单
- 最近5笔订单：{recentOrders} （订单号、客户、金额、状态、日期）

### 热销商品 Top 5
{topProductsTable}

### 客户概况
- 总客户数：{totalCustomers}
- 最近新增客户：{recentCustomers}
```

#### 4.3 调用 LLM API

使用 RestTemplate 调用 DeepSeek API（OpenAI 兼容格式）：
```java
Map<String, Object> body = Map.of(
    "model", model,
    "messages", List.of(
        Map.of("role", "system", "content", systemPrompt),
        // 拼接历史消息
        ...
        Map.of("role", "user", "content", request.getMessage())
    ),
    "temperature", 0.3,   // 低温度，减少编造
    "max_tokens", 1500
);
ResponseEntity<Map> response = restTemplate.postForEntity(apiUrl, body, Map.class);
// 解析 choices[0].message.content
```

#### 4.4 防 AI 乱答的多层防护

| 层级 | 策略 | 说明 |
|------|------|------|
| System Prompt | 角色锁定 + 规则约束 | 第一道防线，明确边界 |
| 数据注入 | 只提供真实 DB 数据 | 不给 AI 任何"想象空间" |
| Temperature | 设为 0.3（低） | 减少随机性，降低编造概率 |
| 后置过滤 | 检查返回值是否包含"暂无该统计数据"逻辑 | AI 应自觉遵守，若违反可降级回复 |
| Token 限制 | max_tokens=1500 | 防止长篇编造 |

### 步骤 5：后端 — AI Controller

**新建**: `backend/src/main/java/com/productsell/controller/AIController.java`

```java
@RestController
@RequestMapping("/api/ai")
@RequiredArgsConstructor
public class AIController {
    private final AIService aiService;

    @PostMapping("/chat")
    public Result<ChatResponse> chat(@RequestBody @Valid ChatRequest request) {
        ChatResponse response = aiService.chat(request);
        return Result.success(response);
    }
}
```

**安全**: `/api/ai/**` 不在 SecurityConfig 白名单中，自动被 Spring Security 拦截要求 JWT 认证。无需修改 SecurityConfig。

- 发送按钮带 loading 状态
- 自动滚动到底部（`nextTick` + `scrollTop`）

#### 8.3 Markdown 渲染


- 无 props（独立组件，内部管理状态）
- emit: `close` — 关闭面板

## 验证方案

### 后端验证
1. 启动后端，用 Postman/curl 调用 `POST /api/ai/chat`，传入 `{"message":"今天销售额多少？","history":[]}`，验证：
   - 返回的 reply 包含系统真实数据
   - 回复格式为 markdown，分段清晰
2. 传入无关问题 `{"message":"今天天气怎么样？","history":[]}`，验证返回拒绝回复
3. 传入 `{"message":"仓库里还有多少货？","history":[]}`，验证库存数据准确

### 前端验证
1. 登录系统，点击右下角 AI 浮动按钮 → 抽屉滑出
2. 在输入框输入"订单最多的客户是哪个？"，发送 → 观察 AI 回复
3. 验证 markdown 渲染正确（标题、表格、列表样式正常）
4. 关闭抽屉 → 重新打开 → 对话历史保留（组件未销毁时）
5. 多次对话验证上下文连续性
6. 点击抽屉外部遮罩区域 → 抽屉关闭（`close-on-click-modal` 可设为 false 防止误关）

### Prompt 有效性验证
1. **闲聊测试**："讲个笑话" → AI 应拒绝
2. **数据虚构测试**："明年销售额预测多少？" → AI 应回复"暂无该统计数据"
3. **越界测试**："帮我写一段Python代码" → AI 应拒绝
4. **数据准确性**：对比 AI 回复中的数字与系统统计数据页面的数字，确保一致

### 安全验证
1. 未登录状态下直接请求 `/api/ai/chat` → 返回 401
2. 普通用户(USER)可使用 AI 对话 → 正常（不限制角色）
3. AI API key 不在前端代码中暴露 → 通过 Network 面板确认
